# Material unresolved issues

1. **Historical timing lineage.** The authors report i7-9700K, 32 GB, Ubuntu 18.04 for the 3,600 formal measurements. Those runtime/status cells are retained. The actual formal executable/source revision, input checksums and execution logs have not been recovered. Matching query IDs alone cannot establish that they measured Algorithms 1–4 under the current score/time semantics. Current publication-source hashes explicitly do not certify the source of old timings.
2. **Historical clock/query interpretation.** Raw schedules use HHMMSS; processed schedules correctly use elapsed seconds. All 28,342 archived route sequences pass raw-integer-clock structural replay; none passes processed-second replay with the released unchanged query values. Read as seconds, 855/1,260 starts occur after the last released scheduled arrival. The fields cannot all be repaired by HHMMSS conversion: 80 starts and 278 ends are invalid HHMMSS encodings. Do not invent corrected windows or assume original query intent. A new run with unchanged values is valid only for those literal inputs.
3. **Archived A*/AP scores.** Query-dwell replay disagrees on 1,146/22,775 records (A*:623; AP:523). Original station-dwell files explain 325 of them. Under that earlier rule 821 remain (20 are within 1e-5 absolute difference; 801 exceed 0.1). Rescoring a fixed route does not prove it remains an exact best route. The old 240-query quality table, mean 0.94 and 224 matches remain historical claims, not newly validated ones. Raw-clock diagnostic outputs are explicitly labelled and do not replace physical-second runs.
4. **Original source schema.** The original measurement tables in the archival A/AP ZIP contain appended mixed-schema rows. Its 35,472 rows cannot safely be merged by interpreting a numeric query_id as query_no and selecting maximum scores: that provisional mapping produces 5,096 duplicate rows; 648 path identities have differing recorded precision, including 10 differences exceeding 1e-6. The released historical 22,775-row subset remains traceable; no conflicting appended results are silently admitted as verified evidence.
5. **Dataset and manuscript statistics.** Released Austin has 2,683 vertices / 535,542 edges / mean out-degree 199.6056653; Houston has 9,094 / 1,446,762 / 159.0897295. Table 2 in the revised manuscript matches this released snapshot. This documentation correction does not establish which network version produced the historical timing records.
6. **Upstream provenance.** Original GTFS feed/version, acquisition and service dates, POI-source snapshot/500 m matching record, cost interpretation and redistribution licenses are not completely present. Prepared inputs and hashes preserve the available snapshot but cannot reconstruct missing provenance. GTFS Validator is software, not the dataset source.
7. **Resource-limited new exact runs.** A*: {'no_route': 1052, 'ok': 154, 'resource_limit': 54}；AP: {'no_route': 1052, 'ok': 208}；路径记录 2,080 条，独立路径/得分核查失败 0 条。 Resource-limited A* attempts are excluded from exact-reference quality statistics; they cannot be recoded as no-route, timeout or successful optima. 新质量子集 110 条；均值 1.00000000，中位数 1.00000000，IQR [1.00000000, 1.00000000]；110 条最佳得分相同；AP>A* 为 0 条。

These issues do not invalidate the inspected theoretical definitions/proofs by themselves. They limit which empirical claims can be made. They cannot be removed merely by editing a README, replacing old scores, or attaching a path from another query.
